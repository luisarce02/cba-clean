The problem

Overflowing containers and accumulated waste are easy for residents to spot, but hard for operational teams to track without a reliable bridge between citizen observations and operational action. CBA Clean is inspired by this gap in Cochabamba, Bolivia.

This is an independent engineering project — it does not claim official use by the municipality. Its value is as a design laboratory anchored in a real community challenge.

Why it was built

Instead of building another CRUD application, CBA Clean was designed around a real operational workflow and used to explore distributed systems, event-driven architecture, security, reliability, testing and CI/CD with Java and Spring Boot.

  • Explore how software engineering can serve a local problem.
  • Demonstrate production-oriented practices — not a tutorial.

Workflow .github/workflows/ci.yml · PR + push to main. No deployment claimed.

Reporter never writes an incident directly. POST /api/v1/reports commits reports + outbox_events atomically; report.created via RabbitMQ opens the incident idempotently. Operator drives the lifecycle via GET and PATCH /api/v1/incidents/{id}/status.

Text version for assistive technology

Left to right: Reporter submits via Angular 21 and Nginx to Report Service on 8080 which writes report and outbox event in one PostgreSQL transaction. Outbox publisher polls with SKIP LOCKED and waits for RabbitMQ publisher confirms on exchange cba-clean.events routing key report.created. RabbitMQ with retries 2s 4s 8s via DLX to DLQ delivers to Incident Service on 8081 which claims eventId in MongoDB processed_events and creates incident in MongoDB 7. Operator via Angular dashboard reads incidents via GET and updates status via PATCH through lifecycle NEW, ASSIGNED, IN_PROGRESS to RESOLVED or CANCELLED. Keycloak 26 provides OIDC PKCE and JWT with roles REPORTER and OPERATOR. Observability via Correlation IDs, Actuator and Prometheus. CI enforces tests and Docker build before merge to protected main.
